## 4.1.1. Basis Data (Database Design)
Untuk merancang dan menjelaskan basis data, Anda perlu menyiapkan diagram dan tabel berikut:

1. **Entity Relationship Diagram (ERD)**
   *   **Fungsi**: Memvisualisasikan entitas dan relasi antar tabel.
   *   **Entitas Utama yang harus ada**: `User`, `Post`, `Skill`, `Comment`, `Report`, `OtpVerification`.
   *   **Relasi yang harus digambarkan**: 
       *   *Many-to-Many*: User ke Skill (tabel `user_skills`), Post ke Skill (tabel `post_skills`), User ke Post untuk ketertarikan (tabel `post_interests`).
       *   *One-to-Many*: User ke Post, User ke Comment, Post ke Comment.
       *   *Self-Referencing*: Comment ke Comment (untuk *nested replies* melalui `parent_id`).

2. **Logical Record Structure (LRS) / Skema Relasi Antar Tabel**
   *   **Fungsi**: Diagram turunan dari ERD yang memperlihatkan *Primary Key* (PK) dan *Foreign Key* (FK) yang dihubungkan dengan garis relasi.

3. **Spesifikasi Basis Data (Kamus Data)**
   *   **Fungsi**: Penjelasan detail dalam bentuk tabel untuk setiap entitas.
   *   **Isi Tabel**: Nama Field, Tipe Data (contoh: `VARCHAR`, `INT`, `TIMESTAMP`), Ukuran/Panjang, Keterangan (Primary Key / Foreign Key).
   *   *Contoh*: Anda harus membuat tabel spesifikasi untuk tabel `users`, tabel `posts`, tabel `skills`, dsb.

## 4.1.2. Algoritma Sistem (System Algorithms)
Pada bagian ini, dijelaskan metode utama yang digunakan untuk menyelesaikan permasalahan pencarian dan penyaringan data pada aplikasi BiConnect. Aplikasi ini mengandalkan kemampuan sistem *Database Management System* (DBMS) relasional melalui abstraksi *Object-Relational Mapping* (ORM) Laravel Eloquent.

### A. Algoritma Pencarian String Dasar (Basic String Matching)
Algoritma pencarian yang digunakan oleh penulis untuk menemukan postingan proyek, diskusi, atau profil pengguna adalah algoritma pencocokan *string* sederhana. Algoritma ini murni memanfaatkan operator `LIKE` pada SQL untuk mencari *substring* yang cocok di dalam *field* tertentu pada *database*.

Pendekatan ini dipilih karena:
1.  Sangat ringan dan cepat untuk *dataset* berukuran kecil hingga menengah seperti pada lingkup mahasiswa UBSI.
2.  Tidak memerlukan konfigurasi *database* eksternal tambahan.
3.  Cukup untuk memenuhi kebutuhan pencarian berdasarkan judul atau isi postingan.

**Cara Kerja Pencarian:**
1.  Sistem menerima *input* kata kunci (*keyword*) dari pengguna.
2.  Sistem membersihkan *keyword* dari karakter berbahaya atau *tag* HTML (sanitasi).
3.  Sistem mengeksekusi *query database* untuk mencari *record* dimana kolom `title` atau `body` mengandung pola pencarian.
4.  Hasil yang cocok dikembalikan dan diurutkan berdasarkan waktu pembuatan terbaru.

**Listing Program Algoritma Pencarian:**
Berikut adalah cuplikan kode implementasi algoritma pencarian menggunakan metode `LIKE` pada `SearchController.php`:
```php
public function search(Request $request): JsonResponse
{
    // 1 & 2. Terima dan bersihkan input keyword
    $query = trim(strip_tags($request->query('query')));

    // 3. Proses pencocokan string dengan klausa LIKE pada tabel Posts
    $posts = Post::query()
        ->with(['user', 'skills'])
        ->active()
        ->when($query, function ($q, $query) {
            $q->where('title', 'like', "%{$query}%")
              ->orWhere('body', 'like', "%{$query}%");
        })
        ->latest() // 4. Urutkan berdasarkan waktu terbaru
        ->paginate(5);

    return response()->json(['posts' => $posts]);
}
```

### B. Algoritma Filter dan Pengurutan Berbasis Relasi (Relational Filtering & Sorting)
Selain pencarian teks, fitur inti dari BiConnect adalah menyaring *feed* berdasarkan kategori dan keahlian (*skills*). Mengingat relasi antara postingan dan keahlian adalah relasi *Many-to-Many* (banyak ke banyak), algoritma penyaringan harus memeriksa tabel perantara (`post_skills`).

Penulis menerapkan metode *Relational Filtering* dengan menggunakan fungsi bawaan `whereHas` pada Laravel Eloquent. Fungsi ini bekerja dengan cara membuat sub-*query* SQL `EXISTS` secara dinamis untuk memastikan bahwa postingan yang ditarik hanya yang memiliki relasi dengan ID keahlian yang dipilih pengguna.

Setelah disaring, sistem menggunakan algoritma pengurutan (*Sorting*) berdasarkan dua opsi:
1.  **Terbaru (Latest)**: Mengurutkan postingan murni berdasarkan waktu perilisan (`created_at` menurun).
2.  **Terpopuler (Popular)**: Mengurutkan postingan berdasarkan tingkat interaksi tertinggi, yaitu kombinasi kalkulasi jumlah *likes* dan jumlah *comments*.

**Listing Program Algoritma Filter & Pengurutan:**
Berikut adalah cuplikan kode dari `FeedController.php` yang mengimplementasikan logika penyaringan relasi dan pengurutan popularitas:
```php
public function index(Request $request): View
{
    // Mengambil data postingan beserta metrik interaksi
    $query = Post::query()
        ->with(['user', 'skills'])
        ->withCount(['comments', 'likes', 'interests'])
        ->active();

    // 1. Algoritma Relational Filtering (Tabel Many-to-Many)
    if ($request->filled('skills')) {
        $skillIds = is_array($request->skills) ? $request->skills : explode(',', $request->skills);
        $query->whereHas('skills', function ($q) use ($skillIds) {
            // Hanya ambil postingan yang memiliki keahlian sesuai array ID
            $q->whereIn('skills.id', $skillIds);
        });
    }

    // 2. Algoritma Pengurutan (Sorting)
    $sort = $request->get('sort', 'latest');
    if ($sort === 'popular') {
        // Jika terpopuler, urutkan berdasarkan jumlah interaksi terbanyak
        $query->orderByDesc('likes_count')
              ->orderByDesc('comments_count')
              ->orderByDesc('id');
    } else {
        // Default: urutkan berdasarkan waktu rilis terbaru
        $query->latest();
    }

    $posts = $query->paginate(10)->withQueryString();

    return view('feed.index', compact('posts'));
}
```
